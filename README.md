# Бот «Приймальня Ангарта» — @anghartainfobot

Telegram-бот замовлень Видавництва «Ангарта»: каталог → корзина → оплата з фото
квитанції → анкета клієнта → рядок у Google Таблиці. Плюс звʼязок із клієнтами
через адмін-тему і масова розсилка.

Стек: **aiogram 3** (long polling), **Google Sheets API** як сховище, SQLite для
службового стану.

---

## Що вміє

### Клієнт (приват із ботом)

- `/start` — вітання і меню: **🛒 Замовити** / **✉️ Зв'язок**
- **Зв'язок** — усе написане пересилається в адмін-тему; відповідь адміна
  повертається клієнту
- **Замовити** — категорії (Журнали, Мерч) → товар → кількість
- Щойно в корзині зʼявляється позиція, знизу виникає велика кнопка **🛒 До корзини**
- Корзина → реквізити для оплати (клікабельні, копіюються тапом) → фото квитанції
- Анкета: телефон → ПІБ → область/район/місто → тип отримання → адреса
- Перевірка даних із можливістю змінити будь-яке окреме поле
- `/cancel` — скасувати поточний крок

Уся навігація — inline-кнопки під текстом; перехід між екранами редагує те саме
повідомлення, тож чат не засмічується.

### Адмін (у групі, в темі `BOT_TOPIC_ID`)

| Команда | Що робить |
|---|---|
| `/topicid` | показує ID теми — значення для `BOT_TOPIC_ID` |
| `/pause` (reply) | вимикає авто-відповіді для цього клієнта |
| `/resume` (reply) | вмикає назад |
| `/status <номер> <статус>` | 🟢 Запаковано / 🟡 Не запаковано в колонці A |
| `/orders` | останні незапаковані замовлення |
| `/remnants` | залишки товарів: кнопка на товарі → вкажіть, скільки лишилось |
| `/mailings «товар»` | розсилка reply-повідомлення всім клієнтам **з** кнопкою «🛒 Замовити» |
| `/mailings «івент»` | те саме **без** кнопки |
| **Reply** на повідомлення клієнта | доставляє відповідь клієнту |

У темах форуму Telegram підставляє `reply_to_message` = службове повідомлення
самої теми. Тому «є reply» саме по собі нічого не означає — перевіряйте через
`real_reply()`, інакше звичайне повідомлення в темі виглядає як відповідь.

Нове замовлення приходить у тему **одним повідомленням**: фото квитанції +
підпис із усіма даними. Reply на нього йде клієнту.

**Номер замовлення.** Клієнт бачить час оформлення — `01.09.26 23:02`; він же
лягає у властивість «Номер замовлення» в Notion. Внутрішній `#100+` лишається
для `/status` і живе тільки в SQLite, тому в адмін-темі показані обидва.
Час київський (`Europe/Kyiv`), бо контейнер працює в UTC.

Підказки по «/» ставляться при старті: клієнтам — `/start` і `/cancel`,
в адмін-групі — `/remnants`, `/orders`, `/status`, `/mailings`. Решта команд
(`/pause`, `/resume`, `/topicid`, `/importclients`) працюють, але в підказки
не виносяться — потрібні зрідка або взагалі разово. Окремої області під тему форуму Telegram
не має, тому в групі підказки однакові в усіх темах.

Розсилка тегає кожного персонально: `@username`, а якщо юзернейму немає —
клікабельне імʼя через `tg://user?id=`.

**Залишки.** `/remnants` показує список товарів і скільки їх лишилось. Тап по
товару → бот питає число → воно лягає в SQLite (том `/data`, переживає деплой).
Сам запит «скільки лишилось» теж лежить у базі, а не в памʼяті процесу: деплой
посеред діалогу не лишає адміна з мовчазним ботом. Число можна написати як
окремим повідомленням, так і reply на запит.
Кожне замовлення списує куплене; коли залишок доходить до нуля, товар у каталозі
стає «немає у наявності», а в тему прилітає попередження. Товар без заданої
кількості («не задано») продається без обмежень — облік по ньому не ведеться.

## Google Таблиця

Файл «Shipment_Registry».

### «Предзамовлення» — замовлення

| A | B | C | D | E | F | G |
|---|---|---|---|---|---|---|
| Запаковано | Номер ТТН | Склад замовлення | Телефон | Прізвище | Ім'я | По-батькові |

| H | I | J | K | L | M | N |
|---|---|---|---|---|---|---|
| Тип отримання | Номер/Адреса | Місто | Район | Область | Фіскальний чек | Тип |

- **M** — посилання на повідомлення з квитанцією в адмін-темі
- **N** — бот НЕ заповнює, проставляється вручну
- Дані пишуться в перший вільний рядок, починаючи з 4-го

### «Клієнти» — база розсилки

`User ID | Ім'я | Username | Перший контакт` — поповнюється сама, щойно людина
пише боту. Живе в Таблиці навмисно: переживає перезапуск і переїзд на інший хостинг.

### «Шаблони» — авто-відповіді (опційно)

`Ключові слова | Відповідь | Активний`. Ключові слова через кому. Якщо вкладки
немає — авто-відповіді просто вимкнені, бот пише в тему «потрібна відповідь адміна».

## Локальний запуск

```bash
pip install -r requirements.txt
cp .env.example .env      # заповнити реальними значеннями
python main.py
```

Один токен = один процес. Якщо бот уже крутиться деінде, локальний запуск
відвалиться з `TelegramConflictError`.

## Деплой на Railway

1. **New Project → Deploy from GitHub repo** → цей репозиторій
2. **Variables** — додати:
   `BOT_TOKEN`, `ADMIN_GROUP_ID`, `BOT_TOPIC_ID`,
   `GOOGLE_SHEETS_ID`, `GOOGLE_SERVICE_ACCOUNT_JSON` (JSON одним рядком),
   `DB_PATH=/data/bot.db`, `PENDING_PATH=/data/pending_orders.json`
3. **Volume** — створити й змонтувати на `/data`
   (без нього лічильник замовлень і звʼязки reply губляться при кожному деплої)
4. Старт береться з `Procfile`: `worker: python main.py`

Бот на long polling, тому webhook лишається порожнім — це нормально.

### Сервіс-акаунт Google

Ключ створюється в Google Cloud Console (IAM → Service Accounts → Keys → JSON).
Далі `client_email` із цього JSON треба додати як **Редактора** в саму Таблицю
через «Поділитися».

## Структура

```
main.py             точка входу: polling + догрузка офлайн-черги раз на 60 с
config.py           .env → Config
catalog.py          категорії й товари (ціни правити тут)
db.py               SQLite: лічильник замовлень, звʼязки reply, пауза
sheets_service.py   Google Sheets: замовлення, клієнти, шаблони, офлайн-черга
handlers/
  order.py          каталог, корзина, оплата, анкета
  client.py         повідомлення клієнтів → адмін-тема
  admin.py          команди адміна + розсилка
Procfile            worker: python main.py
```

## Офлайн-черга

Якщо Google Таблиця недоступна в момент оформлення, замовлення лягає в
`pending_orders.json`, клієнт усе одно отримує підтвердження, а бот раз на
хвилину пробує довантажити і повідомляє в тему, коли вдалось.
