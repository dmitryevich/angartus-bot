# Telegram-бот замовлень із Notion

Бот на **aiogram 3.x**, який використовує **Notion** як основне сховище даних. Замовлення пишуться у вкладку **«Shipment Registry»** бази **«🧠 Ангарта Operations Hub»** (нове Notion API 2025-09-03, data sources):

- 🛒 покрокова форма замовлення (прізвище → ім'я → по-батькові → телефон → тип отримання кнопками → область → місто → відділення/адреса → склад замовлення) з підтвердженням і `/cancel` на будь-якому кроці;
- 📝 кожне замовлення — новий рядок у «Shipment Registry», клієнт отримує номер замовлення;
- 🤖 авто-відповіді за ключовими словами з бази Notion «Шаблони відповідей» (кеш 5 хв, щоб не перевищувати ліміт Notion API);
- 💬 усі повідомлення клієнтів пересилаються в одну тему «Замовлення» в адмін-групі; відповідь адміна **реплаєм** на повідомлення клієнта бот доставляє клієнту (і ставить реакцію 👌 як відмітку «доставлено»);
- ⚠️ якщо жоден шаблон не спрацював — у темі з'являється позначка «Потрібна відповідь адміна»;
- 🔌 якщо Notion недоступний — замовлення зберігається локально в JSON і довантажується автоматично, адмін отримує сповіщення.

## Команди

**Клієнт (приват):**
| Команда | Дія |
|---|---|
| `/start` | привітання |
| `/order` | оформити замовлення |
| `/cancel` | скасувати оформлення на будь-якому кроці |

**Адмін (у групі):**
| Команда | Дія |
|---|---|
| `/pause` | (reply на повідомлення клієнта) вимкнути авто-відповіді — бот мовчить, відповідає тільки адмін |
| `/resume` | (reply на повідомлення клієнта) увімкнути авто-відповіді назад |
| `/status <номер> <статус>` | змінити статус замовлення в Notion, напр. `/status 12 в роботі` |
| `/orders` | останні 10 замовлень зі статусом «🟡 Нове» |
| `/topicid` | показати ID поточної теми (для налаштування `BOT_TOPIC_ID`) |

---

## 1. Створіть бота в Telegram

1. Напишіть [@BotFather](https://t.me/BotFather) → `/newbot` → отримайте **BOT_TOKEN**.
2. `/setprivacy` → виберіть бота → **Disable** (щоб бот бачив повідомлення в групі).

## 2. Налаштуйте адмін-групу

1. Створіть групу, у **налаштуваннях групи увімкніть «Теми» (Topics)** — група стане форумом.
2. Додайте бота в групу і зробіть його **адміністратором** із правом **«Керування темами» (Manage Topics)**.
3. Дізнайтеся ID групи: додайте в групу [@getidsbot](https://t.me/getidsbot) або перешліть повідомлення з групи боту [@userinfobot](https://t.me/userinfobot). ID має формат `-100xxxxxxxxxx` — це **ADMIN_GROUP_ID**.

### Тема «Замовлення» (єдина тема бота)

Бот працює в **одній** темі групи: туди пересилаються всі повідомлення клієнтів, туди ж падають нові замовлення й службові сповіщення. Теми колективу бот не чіпає.

1. Створіть у групі тему **«Замовлення»**.
2. Напишіть у ній `/topicid` (після запуску бота) — бот відповість ID теми.
3. Додайте в `.env`: `BOT_TOPIC_ID=<цей ID>` і перезапустіть бота.

Як відповідати клієнтам: зробіть **reply** на переслане повідомлення клієнта (або на картку замовлення) — бот доставить текст клієнту в приват і поставить реакцію 👌. `/pause` та `/resume` теж працюють реплаєм на повідомлення клієнта. `/orders` і `/status` працюють тільки в цій темі.

## 3. Створіть інтеграцію Notion

1. Відкрийте [notion.so/my-integrations](https://www.notion.so/my-integrations) → **New integration**.
2. Назва — будь-яка (напр. «Telegram Bot»), workspace — ваш.
3. Capabilities: увімкніть **Read content**, **Insert content**, **Update content**.
4. Скопіюйте **Internal Integration Secret** (починається з `ntn_` або `secret_`) — це **NOTION_TOKEN**.

## 4. Бази даних у Notion (вже налаштовано ✅)

Бот працює з існуючими базами workspace **«Ангарта Task-Manager»**:

### «Shipment Registry» (вкладка бази «🧠 Ангарта Operations Hub»)

Ваші колонки: `Номер ТТН` (Title), `Прізвище`, `Ім'я`, `По-батькові`, `Телефон`, `Тип отримання` (Select: Відділення / Поштомат / Адресна доставка / Укр.пошта), `Область`, `Район`, `Місто`, `Номер / Адреса`, `Склад замовлення`, `Запаковано`, `Тип`, `Фото чека`.

Додані службові колонки для бота: `№ замовлення` (Number), `Дата` (Date), `Статус` (Select: 🟡 Нове / 🔵 В роботі / 🟢 Виконано / 🔴 Скасовано), `User ID` (Number), `Username` (Text).

> Колонку «Номер ТТН» (title) бот **не заповнює** — вона залишається порожньою, доки ви не впишете реальну ТТН при відправці. Нові рядки від бота шукайте за колонками «№ замовлення», «Дата» і «Статус».

### «Шаблони відповідей» (окрема база, вже створена)

| Властивість | Тип | Примітка |
|---|---|---|
| `Ключові слова` | Title | ключові слова **через кому**, напр. `доставка, скільки їде` |
| `Відповідь` | Text | текст, який бот надішле клієнту |
| `Активний` | Checkbox | бот враховує **тільки увімкнені** записи |

Пошук за ключовими словами нечутливий до регістру; спрацьовує, якщо повідомлення клієнта **містить** будь-яке зі слів. Шаблони кешуються на **5 хвилин** — зміни в Notion підтягнуться не миттєво.

## 5. Підключіть інтеграцію до баз

Для **обох** баз — «🧠 Ангарта Operations Hub» і «Шаблони відповідей»: відкрийте базу → меню `•••` (угорі праворуч) → **Connections** (або **Share → Connect**) → знайдіть свою інтеграцію → **Confirm**. Без цього кроку API повертатиме 404.

## 6. ID data source-ів (вже відомі ✅)

Operations Hub — база з **кількома вкладками (data sources)**, тому в конфігурації використовуються ID саме data source-ів, а не бази цілком. Вони вже вписані в `.env.example`:

```
NOTION_ORDERS_DB_ID=61c71850-0d25-422e-806e-9616588b3c6a      # Shipment Registry
NOTION_TEMPLATES_DB_ID=0ec0fbb7-52d8-49c4-a526-911a26662691   # Шаблони відповідей
```

## 7. Запуск локально

```bash
python -m venv venv
venv\Scripts\activate        # Windows  (Linux/Mac: source venv/bin/activate)
pip install -r requirements.txt
copy .env.example .env       # Windows  (Linux/Mac: cp .env.example .env)
# заповніть .env своїми значеннями
python main.py
```

## 8. Деплой на Railway через GitHub

1. Запуште проєкт у GitHub-репозиторій (`.env` у `.gitignore` — секрети не потраплять у git).
2. Зайдіть на [railway.app](https://railway.app) → **New Project** → **Deploy from GitHub repo** → виберіть репозиторій.
3. У сервісі відкрийте вкладку **Variables** і додайте:
   `BOT_TOKEN`, `ADMIN_GROUP_ID`, `NOTION_TOKEN`, `NOTION_ORDERS_DB_ID`, `NOTION_TEMPLATES_DB_ID`.
4. Railway визначить Python за `requirements.txt`; старт-команда береться з `Procfile` (`worker: python main.py`). Якщо потрібно — задайте **Start Command** вручну: `python main.py`.
5. **Рекомендовано:** додайте **Volume** (напр. змонтований у `/data`) і задайте змінні
   `DB_PATH=/data/bot.db` та `PENDING_PATH=/data/pending_orders.json` — інакше зв'язки «клієнт ↔ тема», лічильник номерів замовлень і офлайн-черга обнуляться при кожному редеплої.
6. Натисніть **Deploy** — бот запуститься автоматично при кожному push у репозиторій.

## Структура проєкту

```
main.py              # точка входу, фонова догрузка офлайн-черги
config.py            # конфігурація з .env
db.py                # SQLite: клієнт ↔ тема, пауза, лічильник замовлень
notion_service.py    # Notion: замовлення, шаблони (кеш 5 хв), офлайн-черга JSON
topics.py            # створення форум-тем в адмін-групі
handlers/
  order.py           # FSM-форма замовлення
  client.py          # повідомлення клієнтів: пересилання + авто-відповіді
  admin.py           # /pause /resume /status /orders + доставка відповідей
```

## Як це працює всередині

- **Номер замовлення** генерується локальним лічильником (SQLite) і записується в title Notion як `#12 Ім'я` — саме за ним працює `/status 12 ...`.
- **Офлайн-черга:** якщо Notion не відповів, замовлення падає в `pending_orders.json`; фонова задача раз на 60 с пробує довантажити чергу і сповіщає адмін-групу про успіх.
- **Ліміт Notion API** (3 запити/сек) не перевищується: шаблони читаються не частіше ніж раз на 5 хвилин, решта запитів — поштучні.
